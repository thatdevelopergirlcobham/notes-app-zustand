Mastering Zustand

A step-by-step guide to understanding State Management in your Notes App.

1. What is State Management?

State is just data that changes over time (like a user's name, or a list of notes).

In a small app, you keep state inside a component using useState. But what happens when Navbar needs to show the user's name, but the SettingsPage is where you edit the name?

🏛 The Office Analogy

Local State (useState): You define a rule: "Keep this sticky note on My desk." Only you can see it. If someone else needs it, you have to verify it and pass it to them manually.

Global State (Zustand): You install a giant Whiteboard in the hallway. Anyone can look at it. Anyone (with permission) can write on it. If the boss writes "Urgent Meeting" on it, everyone sees it instantly without talking to each other.

2. Anatomy of Your Store (`useNotesStore.ts`)

Let's dissect the file store/useNotesStore.ts line by line.

Step A: The Shape (Interface)

First, we tell TypeScript what our "Whiteboard" looks like. We list the Data and the Actions (functions to change data). 

interface NotesState {
  // --- THE DATA ---
  notes: Note[];
  user: UserProfile;
  searchQuery: string;
  
  // --- THE ACTIONS ---
  addNote: (note: Note) => void;
  deleteNote: (id: string) => void;
  // ... other actions
}

Step B: The Creator (`create`)

This is the magic function from Zustand. It creates the hook.

export const useNotesStore = create<NotesState>((set) => ({
  // 1. Initial Data
  notes: INITIAL_NOTES,
  user: { name: "Alex", ... },
  searchQuery: "",

  // 2. Implementation of Actions
  addNote: (note) => set((state) => ({ 
    notes: [note, ...state.notes] 
  })),
}));

The `set` function is the key. To change the state, you call set. You provide a function that receives the current state and returns the changes (like a patch).

3. Using it in components

Now, let's look at app/notes/page.tsx. You don't need to wrap your app in a Provider (like Context API). You just import the hook!

Reading Data & Actions

// app/notes/page.tsx
import { useNotesStore } from "@/store/useNotesStore";

export default function NotesPage() {
  // You just call the hook!
  // We extract 'notes' (data) and 'addNote' (action)
  const { notes, addNote } = useNotesStore();

  // ... rest of your component
}

When notes changes in the store, NotesPage will automatically re-render to show the new list.

5. Advanced Logic: The Pinning Feature

You asked to limit pins to 3. Notice we handled this logic inside the store, not the component. This is best practice. 

togglePin: (id) => set((state) => {
  const note = state.notes.find((n) => n.id === id);
  
  // LOGIC: Check constraints BEFORE updating
  if (!note.isPinned) {
      const pinnedCount = state.notes.filter((n) => n.isPinned).length;
      if (pinnedCount >= 3) {
          alert("Limit reached");
          return state; // Return existing state (do nothing)
      }
  }

  // UPDATE: Actually flip the boolean
  return {
    notes: state.notes.map(...)
  };
}),

By keeping this logic in the store, any component that tries to toggle a pin (a button in card, a keyboard shortcut, etc.) will obey the "Max 3" rule automatically!

6. Try it yourself!

To truly understand expectation vs reality, try adding a new feature:

  1. Open store/useNotesStore.ts
  2. Add a simple clearAll() function to the NotesState interface.
  3. Implement it in create():
    clearAll: () => set({ notes: [] })
  4. Go to app/notes/page.tsx, pull it from the hook: const { clearAll } = ...
  5. Add a button <button onClick={clearAll}>Clear</button>
  6. Watch all notes vanish instantly!
